# 当前部署验收清单（0.1.0 / Early Access）

本清单用于自己的 Linux / systemd、本人单账号私聊部署。复用时每项从待验证开始，填写版本、日期、布尔结果、计数和固定错误类别。[历史真人记录](history/REAL_VALIDATION.md)提供已有证据；下面的历史证据栏不能代替本次部署验收。本地测试、callback `2xx` 与 API `accepted` 也不能代替手机端确认。

不要记录真实 Tunnel identity、个人路径、微信 owner、token、callback URL / secret、二维码、手机号、消息正文、文件名或附件内容。消息 ID 可用本地测试编号代替。

## 首次部署：保持微信接收关闭

- [ ] 绑定来自明确选中的原 account，或明确完成了新二维码登录。
- [ ] 已理解微信绑定、OpenClaw 历史与 dot 会话分别管理，不会自动迁移历史；新二维码登录也不保证使用原机器人 / 对话。
- [ ] 所有可能消费相同绑定的旧服务和其他主机均已停止。
- [ ] 密钥检查 `key_ready: true`，未输出密钥内容。
- [ ] 本地状态为 `bound: true`、`enabled: false`。
- [ ] 官方 Tunnel client 本机健康 / ready 检查通过，MCP 和健康监听未开放公网入口。

先在暂停状态完成插件与订阅配置。已有正常部署只做功能复验时，保留现有插件、任务、绑定和唯一订阅。

## 产品侧 discovery

- [ ] 私人插件选择 Connection **Tunnel**，Tunnel / 插件实际仅本人可访问。
- [ ] 产品工具扫描成功，实际发现 [工具清单中的全部 11 个工具](DOT_SETUP.md#工具清单)，没有多余工具。
- [ ] 事件扫描实际发现 `weixin.message`，delivery 为 webhook。
- [ ] 插件加入原有 dot，并成功调用状态工具；首次部署仍为 paused。

MCP Events 使用 `2026-07-28` discovery。使用旧版 `initialize` 时核对协商版本是否受支持；本地 `tools/list` fixture 不能代替产品扫描，工具扫描也不能代替 Events 能力确认。刷新后原 dot 仍看到旧工具时检查客户端加载状态，必要时重启原 dot，保留唯一订阅。

## 订阅与 callback

- [ ] 空 callback allowlist 拒绝未经批准的目的地，Events 不含微信正文。
- [ ] 从安全状态观察 hostname，再从本人可信产品界面独立确认精确主机，未自动批准任意请求域名。
- [ ] 私人配置使用准确小写 hostname，没有 URL、IP、通配符或路径。
- [ ] 首次配置变更在停服后进行，重启后在原 dot 订阅。
- [ ] 签名 challenge 验证通过，状态显示一个有效订阅，没有第二个聊天 / callback。
- [ ] 有限订阅返回到期时间；明确 `ttlMs: null` 时 `refreshBefore: null`；返回 `cursor: null` 与 `truncated: false`。

challenge 使用 `{type: verification, challenge: ...}`，应成功回显；事件 `data` 只有消息 ID。记录中不要放 challenge、完整请求或签名 header。

## 开启与最小文字闭环

- [ ] 再次确认单接收者，停服务后执行 `resume --confirm-single-consumer`，再启动原服务。
- [ ] 状态显示 enabled、Tunnel ready、一个有效订阅；没有尚未核对的发送中 / `uncertain` 回复。
- [ ] 微信发送一条有唯一测试标记的短文字，持久队列新增一条来信。
- [ ] 原 dot 收到一个消息 ID 事件并读取同一来信，提交一条回复。
- [ ] 发送状态为 `accepted`，本人在同一微信对话确认仅收到一次预期回复。
- [ ] 没有第二个微信接收者或额外模型进程。

`resume` 与 worker 使用同一锁，服务运行期间拒绝 `already_running` 不等于启用成功。`accepted` 只表示腾讯接受请求；没有本人微信端确认时，本项仍待验证。

## 媒体、引用与多次回复

使用同一插件的 11 个工具，保留唯一订阅。下面列出的历史结果来自原部署，自己的结果另行记录。

建议把以下指令一次发给原 dot，随后仅在微信发送测试材料：

> 保留当前任务和订阅。接下来做微信通道验收：收到文件、短视频、语音时按我在微信里的要求处理；语音仅验收接收与转写，不再要求回传；无 ASR 时如实说明。收到引用时说明你实际读到的引用内容。同一条消息可以先用 final:false 发进度，再发最终结果。每条回复检查对应 reply_id 的状态，只有微信端本人确认才记录实际送达。对生成的文本文件使用 stage_weixin_attachment(text_content, kind:auto) 后发送；若生成的二进制文件有可供服务器下载的 HTTPS URL，则用 import_weixin_attachment；仅有 sandbox 路径时如实报告这个限制。

| 手机动作 | 通过标准 | 历史证据（原部署） |
| --- | --- | --- |
| 发一个小文本文件，要求原样回传 | 文件名、内容一致 | 本人确认文件回传成功 |
| 发短视频，要求回传 | 同一对话能播放回传视频 | 本人确认通过 |
| 发语音，要求转述 | 转述符合实际 | 本人确认接收与转写成功；语音回传未收到，本人已取消该项必做验收 |
| 引用旧文字、旧图片分别追问 | dot 说明实际读取的引用内容 | 旧图片两条均确认已回复微信；旧文字待单独验证 |
| 要求先发进度，再生成一段长文 | 同一来信可多次回复，长文分段完整 | 本人确认进度与长文均收到 |
| 要求生成一份带唯一标记的文本文件 | 微信收到可打开的文件 | 本人确认生成 TXT 文件收到且可打开 |
| 提供 dot 生成文件的 HTTPS 链接 | import 后内容校验、手机收到 | 公共 HTTPS 真下载已测；dot 文件来源未确认 |

故障提示不必故意破坏现有任务来测试：其一次性、待处理保留、通知重试不受影响已用模拟数据回归。真实断网 / 服务重启不会自动重发 uncertain；恢复和人工分段确认已有脚本演练。若需要真人断网演练，应安排一个明确测试窗口。

## 可靠性与维护复验

- [ ] 正常重启保留未处理来信与有效订阅，不重发已提交回复。
- [ ] 订阅过期 / 取消后通过 pending 工具显式恢复未提交回复的消息；切换 callback 先取消原订阅。
- [ ] 事件重试耗尽可见，只有明确刷新才开始新的有限重试。
- [ ] `uncertain` 不因重启、订阅或工具重试自动重发，由本人核对后明确处理。
- [ ] 停服务并 pause 后停止微信收发；取消订阅停止 dot 通知。
- [ ] 已在隔离模拟状态验证升级、备份恢复、历史清理预览及容量诊断，恢复副本默认暂停。
- [ ] 测试记录没有正文、登录材料、签名 secret 或运行密钥。

维护步骤见 [OPERATIONS](OPERATIONS.md)。故障只记录固定类别和阶段，保留状态，从失败检查点继续；保持既有私人访问边界。真实异常演练须安排明确窗口，不为了验收故意打断正常任务。
